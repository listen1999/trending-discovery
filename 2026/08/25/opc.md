### 金矿 1：outbid.lol 引爆的"付费排行榜"病毒模型

来源：@levelsio · 2h ago · 👍72 👁17353（转发 @jasperdeboer 的评论文章）；@ecomchasedimond · 多条 · 3h ago 起；@tibo_maker · 1h ago
原始事件：outbid.lol 由 Jonathan Wilke（德国独立开发者，SupaStarter 创始人）于 2026-08-19 23:08 上线，3 小时写完 [经 web_search 交叉验证]。本期（8/24-8/25）出现的是其后续发酵——新的增长数据点、新一批模仿者上线、以及 levelsio/tibo_maker/ecomchasedimond 等人的实时讨论和跟风产品发布，因此构成新信号，非旧素材翻炒。

核心数据（已验证，多来源交叉核实，数字有出入均列出）
- 上线 12 小时内：4,500+ 独立访客（开局几小时），12 小时破 10,000 访问 [来源：automatio.ai]
- 2026-08-22：营收约 $12.5 万（约 ¥84.0 万），访问量 1M+ [来源：bestaiso.com]
- 2026-08-23：营收约 $17.7 万（约 ¥118.9 万），访问量 1.2M+ [来源：bestaiso.com]
- 另有信源报"上线 48 小时内 $12 万营收、100 万访客"[来源：newsfilecorp.com]——与上条数据窗口不同、口径接近，两者互为印证但非同一时间点，故并列标注
- 最高单笔出价：$14,013～$15,000（不同信源数字略有差异）[未完全统一验证]
- 汇率：1 USD ≈ 6.72 CNY（2026-08-24/25 参考价）

商业模式拆解
- 机制：任何人提交自己的网站/产品/账号，用真金白银"竞价"排行榜位置，出价最高者排第一，被超越就掉名次
- 定价结构：最低入场 $2（整数美元），前 50 名的最低门槛已被抬到 $401；也支持"补差价"出价（只需付到比当前第一名多 $1）和"三小时霸榜"（付当前最高价的 5 倍锁首页 3 小时）
- 技术栈：Next.js + Postgres + Polar（作为 Merchant of Record 处理支付，规避了创始人自己对接多国税务的麻烦）
- 收入公式：单一维度——总提交人数 × 平均出价，没有订阅、没有广告位分层，胜在极简和病毒式抢位心理
- 護城河：几乎为零。代码逻辑任何人一晚能写完，唯一的护城河是"先发的流量池"

同赛道的两个真实案例（体现规模分层）
1. **thebiggestad.com**（@ecomchasedimond，邮件营销博主，16.9 万粉丝，自述数据）：同一机制的"广告位"版本，8/22 上线，8/25 已有 53 家公司买过位置，当前最高出价 $85（约 ¥571），3 天内 4,562 次访问。规模比 outbid.lol 小两个数量级，但证明了"小池塘"也能跑起来，且已经在做二次运营（赞助商目录页、分类页、公开成交记录、里程碑倒计时）来延长产品寿命
2. **winbid.lol**（国内开发者 @meepo，经 indie_maker_fox 转发）：用 TanStarter 模板 40 分钟复刻上线，是本期国内唯一已知的可验证复刻案例

复制路径（只写真正适用的档位）
- 档位 B（独立开发者）：这类产品技术复杂度低，核心壁垒在"谁先发、谁的种子流量池够大"。有现成海外收款经验（Stripe/Polar）的开发者可以快速复刻，但当前 190+ 个同类站点已经严重分流注意力，新入场者拿到有效出价的概率在持续下降
- 档位 C（工具集成者）：可以用 Cursor/Claude Code + TanStarter/类似模板在几十分钟内出一个 MVP（winbid.lol 就是例子），价值不在技术难度，而在选一个还没被占的垂直切口（如 thebiggestad.com 选了"广告位"这个细分）
- 档位 D（服务变现者）：可以把"帮你的客户在这类排行榜上买首位曝光"包装成一次性引流服务，但需要向客户说清楚——这是纯注意力购买，无长期 SEO 或复购价值

竞争格局
- 190+ 模仿者在几天内涌现，包括反向机制（"betteroutbid" 反向拍卖、"bottombid" 倒排）等变体 [来源：automatio.ai]
- outbid.lol 本体已收到 $10 万级别的收购意向 [来源：bestaiso.com]，创始人尚未卖出

成本与时间预期
- 冷启动预算：域名 + Polar/Stripe 接入基本零成本，模板复刻（如 winbid.lol）40 分钟即可上线 [来源：indie_maker_fox 转发内容，未独立核实工时统计口径]
- 稳定后运营预算：需进一步调研（该类产品尚无"稳定期"案例，均处于爆发或衰退曲线上，没有可参考的长期运营成本基线）

深度综述
outbid.lol 最反直觉的地方，不是它的技术（这是 SaaS 里最不值钱的部分），而是它把"公开羞辱式竞争"做成了商业模式——每个买家都知道自己随时会被出更高价的人顶掉，这种损失厌恶心理才是真正的付费驱动力，比任何订阅制的粘性都强，但也意味着它没有复购逻辑，一旦新鲜感过去就会迅速衰退，这也是为什么 bestaiso.com 的分析直接指出它"缺乏留存机制"、收购报价背后其实是创始人自己也在评估"要不要趁热卖掉"。从趋势定位看，这是"分发即产品"这个思路的又一次极端化演绎——不生产内容、不解决具体问题，只是把注意力本身做成了可交易品，这条思路今年在 indie hacker 圈子里已经出现过好几轮（此前的 TrustMRR、各类"today's best builder"打榜站都是同源变体，见金矿 2）。对中国创业者最大的障碍不是技术，而是分发渠道——outbid.lol 的原始用户池来自作者本人在 X 上的独立开发者影响力，国内类似"晒收入""打榜"文化的传播土壤（小红书、即刻）尚未验证是否能复现同样的病毒系数，winbid.lol 目前的流量规模未见公开数据，无法判断复刻是否真的跑通，这一点需要读者自行验证而非默认可复制。

### 金矿 3：levelsio 的"一人公司基础设施"——Termius + tmux + Claude Code 全托管跑法

来源：@levelsio（93.6 万粉丝，已验证高收入 solopreneur，附录名单内人物，个人简介自述组合月流水 $80K+$44K+$23K+$20K+$15K）· 2026-08-25 00:31 / 04:32
内容类型：操作贴（对读者提问的详细回复，非完整 Thread，但包含具体可执行步骤）

完整步骤（逐条列出，不压缩，还原自推文原文）
1. 所有网站/产品都部署在 Hetzner 的 VPS 上；体量大的产品（如 Photo AI）独享一台 VPS，其余较小的产品共用一台 VPS
2. 每个项目目录下有一个叫 `tm` 的脚本（levelsio 自己用 Claude Code 写的），执行 `cd /srv/http/项目名 && tm` 就会自动创建/接入一个以项目名命名的 tmux 会话
3. 用 Termius（iOS/跨平台 SSH 客户端）连接这些 VPS，每个项目的 tmux 会话在 Termius 里就是一个独立标签页，手机断线重连后自动回到原来的会话现场
4. 每个 tmux 会话里常驻打开一个 Claude Code 实例
5. 日常工作方式：把用户提交的 bug 报告或功能请求，直接复制粘贴进对应项目 tmux 会话里的 Claude Code（他称之为"clanker"），让 AI 直接处理

前置条件 / 适用人群：已经有多个上线产品、需要在手机/移动状态下持续响应用户反馈的独立开发者；需要基础的 Linux/VPS 运维知识（申请 VPS、装 tmux、配 SSH）
国内可用性：Termius 直接可用；Claude Code 需科学上网访问（国内不可直连）；Hetzner 官方标注国内访问稳定性较差 [参考已知信息，建议实测网络延迟后再决定是否采用]，可考虑替换为国内可直连的云服务商做同等架构
预计耗时：初次搭建（VPS + tmux + 脚本）半天到一天；此后每个新项目接入只需几分钟

可直接复用的核心逻辑（非代码，为流程描述）
"每个项目 = 一个 tmux 会话 = 一个常驻 Claude Code 实例"，通过统一的启动脚本把"连接服务器"和"进入正确的 AI 会话上下文"合并成一步，减少多项目并行时的上下文切换成本

与现有工具链配合（具体场景）：适合已经用 Claude Code/Codex 做日常开发、且同时维护 3 个以上小产品的独立开发者/工具集成者，替代"本地开电脑、开多个终端标签、来回切换项目目录"的传统方式，尤其适合移动办公场景（手机连 Termius 直接下指令）

踩坑预警 / 已知限制：推文原文未提及如何处理多项目并发时的资源争用（同一 VPS 上跑多个 AI 会话的内存/CPU 消耗）；也未说明代码提交前的审核机制，"直接把用户反馈丢给 AI 处理"存在生产环境误改的风险，读者若复制此方案应自行加上人工审核或至少是预发布环境的步骤

竞品对比：常见替代方案是 GitHub Codespaces / Devbox 等云端 IDE，优势是免运维；levelsio 方案的优势是完全自建、无平台锁定，成本随 VPS 规模线性增长而非按用户数收费

官方链接：Termius（termius.com，需自行核实国内访问情况）；Claude Code（claude.ai/code）

深度综述
这条信号的价值不在"用 tmux 管服务器"这个操作本身（这是老运维的常规操作），而在于 levelsio 把它和 AI agent 工作流做了绑定——每个项目不再只是一个代码仓库，而是一个"随时待命的 AI 员工工位"，这是当前"vibe coding"讨论里比较少被提及的一层：多数关于 AI 编程的分享聚焦"怎么写一次性 prompt 生成代码"，levelsio 展示的是"怎么把 AI 编程能力常驻化、变成可以远程随时调度的生产力节点"，这更接近于"一人公司如何雇佣看不见的 AI 团队"这个命题的具体落地形态。从趋势定位看，这属于 vibe coding 讨论从"能不能生成代码"进入"怎么把生成代码的能力工程化、流程化"的中期验证阶段，与金矿 1、2 里"分发和退出机制"的讨论形成互补——如果说 outbid.lol 和 TrustMRR 展示的是"注意力和资产怎么变现"，这条信号展示的是"背后的生产系统怎么低成本搭建"。对中国读者而言，最大的现实障碍是 Claude Code 和部分海外 VPS（如 Hetzner）的访问稳定性，这意味着直接照搬这套架构在国内可能要在"科学上网稳定性"和"更换为国内可直连的等效工具（如国产 AI 编程助手 + 阿里云/腾讯云 VPS）"之间做取舍，后者需要读者自行验证工具链是否有等效替代，本报告不做替代品的具体推荐，因缺乏可靠的公开对比数据。
